# Changes, batches and reverts

## Preview tools

Every change takes two steps. Call the matching `preview_*` tool first (the change tool's name with `preview_` in front, for example `preview_pause_entity`, `preview_enable_entity`, `preview_update_campaign_budget`, `preview_update_bid`, `preview_update_campaign_settings`, `preview_update_conversion_goals`, `preview_update_bidding`, `preview_add_negative_keywords`, `preview_remove_negative_keywords`, `preview_create_search_campaign`, `preview_create_chat_campaign`, `preview_update_chat_ad`, `preview_update_entity_name`, `preview_update_meta_ad_set`, `preview_update_chat_bidding`, `preview_update_context_hints`, `preview_revert_ad_change`, and for batches `preview_pause_entities`, `preview_enable_entities`, `preview_update_bids`, `preview_add_keywords`, `preview_add_ad_groups`, `preview_add_responsive_search_ads`, `preview_add_assets`, `preview_update_ads`, `preview_update_keywords`, `preview_revert_ad_change_batch`), then show the user exactly what will change (account, item, the before and after labels, the guardrails) and ask them to confirm. Only after they reply, in a later turn, call the change tool with the same arguments, the preview's `confirmation_token` (valid for 10 minutes, once) and `user_confirmation`, their reply quoted as they wrote it. Never chain several changes without confirmation; several previews shown together may be confirmed with one reply.

## Write tools

Pass only the arguments a tool takes: an unknown one (also inside an object) is refused with the list of arguments it takes, never ignored. `list_ad_changes` gives each change's value before as `before_summary` and after as `summary`. `list_ad_entities` shows a Meta ad's current text in `meta_ad`, and `editable` says whether `update_meta_ad` can change it: read it before suggesting new copy.

The write tools include `pause_entity`, `enable_entity`, `update_campaign_budget`, `update_bid`, `update_campaign_settings`, `update_conversion_goals`, `update_conversion_action`, `update_bidding`, `add_negative_keywords`, `remove_negative_keywords`, `create_search_campaign`, `create_chat_campaign`, `update_chat_ad`, `update_context_hints`, `update_entity_name`, `update_meta_ad_set`, `update_chat_bidding`, `revert_ad_change`, `pause_entities`, `enable_entities`, `update_bids`, `add_keywords`, `add_ad_groups`, `add_responsive_search_ads`, `add_assets`, `update_ads`, `revert_ad_change_batch`, `archive_recommendation`, `activate_ad_account` and `create_support_request`; the Meta Ads, Performance Max and ChatGPT Ads tools in the other guides work the same way. Each one needs its preview's token (only `run_ad_account_sync` takes none). `list_ad_changes` shows a batch as one entry (`batch`, with its counts and status); pass its `batch_id` to see each item's result. `preview_create_support_request` and `create_support_request` send the user's message to the Roasby team, who reply by email.

## Many items at once

To pause or enable several campaigns, ad groups, ads or keywords of one ad account, call `preview_pause_entities` or `preview_enable_entities` with their `entity_ids` (any mix of types). One preview and one `confirmation_token` cover all of them. Show the user the totals (`item_count`, `allowed_count`, `refused_count`), the items that change and every refusal reason with its count (`refusal_reasons`); refused items stay as they are and confirming changes only the allowed ones. Then call `pause_entities` or `enable_entities` with the same `entity_ids` and the token. A batch is one ad account at a time (`mixed_ad_accounts` otherwise), counts as one change toward the workspace's limits, and a workspace can change only so many items in one batch (`batch_items`): split larger requests into several batches, each with its own preview and confirmation.

## Pending and paused

Changes are pending until the ad platform applies them; check `list_ad_changes` (narrow it with `campaign_id`, which also finds the change that created the campaign, `actor_type` / `actor_name` for who made it, `status` (or `reverted`), and `from` / `to` days). Everything Roasby creates starts paused: a new campaign is paused with its ad groups, keywords and ads ready under it, so tell the user that enabling the campaign (`preview_enable_entity`) starts it.

## Reverts

Roasby never deletes or archives anything in an ad account (dismissing a recommendation only hides the suggestion). Offer to pause instead, and use `preview_revert_ad_change` to undo an applied change, or `preview_revert_ad_change_batch` with its `ad_change_batch_id` to undo every item a batch applied (reverting a new campaign, added ad groups or added keywords pauses them; reverting negative keywords takes away only the ones that change added). A batch is reverted only once it has finished (`change_pending` while it is still being applied: try again later). A change with `partly_applied: true` in `list_ad_changes` went through only in part: tell the user which parts the platform refused (its `failure_reason`); the applied part can still be reverted.

## Changes that cannot be reverted

Every preview says how far a revert would undo the change (`reversibility`: `full`, `partial` or `none`). A change with `none` (creating a Meta Ads audience, a Meta Ads custom conversion or a ChatGPT Ads conversion event, turning on Google Ads brand guidelines, switching away from bidding Roasby could not set back, or archiving a paused Meta Ads or ChatGPT Ads campaign, ad group or ad with `preview_archive_entity` and `archive_entity`, which neither platform can unarchive) is refused with `irreversible_not_allowed` until a workspace owner or admin turns on **Allow changes that can't be reverted** in the workspace settings in Roasby (`allow_irreversible_changes` in `get_current_workspace`): tell the user that, with the link in `user_actions`, and never look for a way around it. When it is allowed, tell the user plainly what cannot be undone (`irreversible_risk`), ask them to confirm the change and then, in a second, separate question, to accept that it cannot be reverted. Pass the first reply as `user_confirmation` and the second as `irreversible_confirmation`, each quoted exactly; the same reply twice is refused. Never make such a change on your own or in a scheduled or unattended run. `list_ad_changes` marks these changes with their `reversibility`.

## Names and ad set settings

- `preview_update_entity_name` / `update_entity_name` rename a campaign, ad group (a Meta Ads ad set) or a Meta Ads or ChatGPT Ads ad (Google Ads and Microsoft Ads ads have no name): to apply the user's naming rules, or to rename a test or a campaign that did not work, which is paused, never deleted. Names are unique among an account's campaigns and a campaign's ad groups, except on Meta Ads.
- `preview_update_meta_ad_set` / `update_meta_ad_set` change a Meta Ads ad set's end date (null takes it away, not for a lifetime budget). Meta does not change a published ad set's pixel or conversion event, so Roasby refuses it: offer a new ad set with that event (`add_meta_ad_set`) and pausing the old one instead.

## ChatGPT Ads edits

- `preview_update_chat_ad` / `update_chat_ad` change a chat card's title (3 to 50 characters), body (at most 100), link or image (`image_url`, a direct https image link; a share link from Google Drive or Dropbox is refused) in place. ChatGPT Ads reviews the ad again before it shows, so say so before the user confirms. Reverting an image change sends the image file it had back. `final_url_suffix` changes only the ad's landing page query parameters (an empty text takes them away), without a new review.
- ChatGPT Ads landing page query parameters (`final_url_suffix`, such as `utm_source=chatgpt&utm_content={ad_id}`; macros `{campaign_id}`, `{ad_group_id}`, `{ad_id}`, `{ad_account_id}`, `{oppref}`, no leading `?`) go on a new campaign, ad group or ad, and on an existing campaign (`preview_update_campaign_settings`) or ad (`preview_update_chat_ad`). Levels combine; for the same key the ad's wins, then the ad group's, then the campaign's. An ad group's is set when it is created.
- `preview_add_chat_ad_group` / `add_chat_ad_group` add an ad group (name, context hints, 1 to 5 ads, optional `cpc_bid_micros`) to a ChatGPT Ads campaign, paused with its ads enabled under it; `preview_add_chat_ad` / `add_chat_ad` add one ad to an ad group, paused. Reverting pauses what was added.
- `preview_update_context_hints` / `update_context_hints` replace an ad group's whole list of context hints.
- `preview_update_chat_bidding` / `update_chat_bidding` switch an ad group between a target cost per click and maximize clicks, or change its target cost per click (ChatGPT Ads bids for clicks only, and aims at the bid as an average since 2026-11-18, so a single click can cost more: say so to the user).
- `update_campaign_settings` sets a ChatGPT Ads campaign's countries and `platforms` (empty: all; empty `countries` is every country, so say that to the user before confirming).
- `get_campaign_performance` shows a ChatGPT Ads campaign's last 30 days by country, device and platform (`breakdowns`).
