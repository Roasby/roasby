# Conversion tracking

Bidding toward conversions and budget advice only make sense when conversions are tracked. Before suggesting a bidding strategy (maximize conversions or conversion value, a target CPA or ROAS) or a budget change, or judging a campaign by its conversions, read `list_conversion_actions` for its ad account (`primary_only`, `include_removed` narrow or widen it) and the campaign's `conversion_goals` in `get_campaign_performance`. Each account says what bidding aims for (`bidding_goals`) and lists its `problems`; each campaign says whether it uses the account's goals or its own (`level`, a `custom_goal_name`) and its own `problems`. Explain each one in plain words: no enabled primary conversion action in the goals bidding uses, a primary action (for example a Google Analytics 4 import) that has not recorded since a date or whose tag is unverified or inactive, a campaign goal without an enabled action, a campaign still bidding on a removed action. A primary action counts toward bidding; a secondary one is only observed. Roasby never creates or removes conversion actions and never changes Google Analytics 4 key events: they are set up in the ad platform (and in Google Analytics), so give the user those steps. What a search campaign bids on can change: `preview_update_conversion_goals` with its `campaign_id` and `level` `account` (the ad account's goals again) or `campaign` with `goal_keys` (Google Ads: the `key` of each goal in the campaign's `conversion_goals.goals` to bid on; every other goal stops bidding) or `conversion_action_ids` (Microsoft Ads: Roasby IDs from `list_conversion_actions`). Roasby never creates a custom goal. On Microsoft Ads a campaign moves neither to nor from the account's goals (`account_goals_not_supported`: Microsoft offers no way to set it back); it changes only between goals of its own. Goals that record nothing under bidding toward conversions are allowed: the preview names each action that is not recording; tell the user. Tell the user each goal the preview says is not recording, and that changing goals restarts automated bidding's learning period. `list_conversion_actions` lists the campaigns with goals of their own in `campaign_goals`. A revert puts back the exact setup before. On Meta Ads, `list_conversion_actions` lists the account's pixels (datasets); each ad set chooses a pixel and an event, so Meta campaigns have no goals to change here.

## Changing a conversion action

A Google Ads conversion action or Microsoft Ads conversion goal can change four settings through `preview_update_conversion_action` and then `update_conversion_action` with the same arguments and the token: `primary` (true: bidding counts it; false: only reported), `counting` (`one` per click for leads and sign-ups, `every` for purchases), `default_value_micros` (the value each conversion gets by default, in micros of the action's `value_currency`: 500 units is 500000000) and `always_use_default_value` (true: every conversion gets that value even when the tag sends one). Pass the action's Roasby `id` from `list_conversion_actions` as `conversion_action_id`, and only the settings that change. `list_conversion_actions` shows the current `default_value_micros`, `value_currency` and `always_use_default_value`.

Before you confirm, tell the user plainly that the change affects **every campaign that bids on this action** (value-based bidding and target ROAS read these values), and that a value change applies to new conversions only. Refusals: `conversion_action_not_synced` (sync first), `conversion_action_shared` (managed in a manager account: change it there), `conversion_action_removed`, `conversion_value_required` (always using the default value needs one: give `default_value_micros` too), `no_change`, and `kind_not_supported` on ChatGPT Ads and Meta Ads. On Microsoft Ads, making a goal secondary needs a feature Microsoft enables only for some accounts: when Microsoft refuses it, say so. A revert puts the settings back as they were.
