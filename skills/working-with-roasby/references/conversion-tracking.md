# Conversion tracking

Bidding toward conversions and budget advice only make sense when conversions are tracked. Before suggesting a bidding strategy (maximize conversions or conversion value, a target CPA or ROAS) or a budget change, or judging a campaign by its conversions, read `list_conversion_actions` for its ad account (`primary_only`, `recording_only`, `status`, `source_name` and `include_removed` narrow or widen it; `total` and `sources` sum the actions per Google Analytics 4 property, UET tag or pixel, so read them before a long table) and the campaign's `conversion_goals` in `get_campaign_performance`. Each account says what bidding aims for (`bidding_goals`) and lists its `problems`; each campaign says whether it uses the account's goals or its own (`level`, a `custom_goal_name`) and its own `problems`. Explain each one in plain words: no enabled primary conversion action in the goals bidding uses, a primary action (for example a Google Analytics 4 import) that has not recorded since a date or whose tag is unverified or inactive, a campaign goal without an enabled action, a campaign still bidding on a removed action. On Microsoft Ads a goal or bidding preview first asks Microsoft which goals still exist, so a goal removed there since the last read shows as removed. A primary action counts toward bidding; a secondary one is only observed. Roasby never removes conversion actions and never changes Google Analytics 4 key events themselves (they are set up in Google Analytics; Google's API cannot import one, so give the user those steps). What a search campaign bids on can change: `preview_update_conversion_goals` with its `campaign_id` and `level` `account` (the ad account's goals again) or `campaign` with `goal_keys` (Google Ads: the `key` of each goal in the campaign's `conversion_goals.goals` to bid on; every other goal stops bidding) or `conversion_action_ids` (Microsoft Ads: the `id` or `platform_id` from `list_conversion_actions`). Roasby never creates a custom goal. On Microsoft Ads a campaign moves neither to nor from the account's goals (`account_goals_not_supported`: Microsoft offers no way to set it back); it changes only between goals of its own. Goals that record nothing under bidding toward conversions are allowed: the preview names each action that is not recording; tell the user. Tell the user each goal the preview says is not recording, and that changing goals restarts automated bidding's learning period. `list_conversion_actions` lists the campaigns with goals of their own in `campaign_goals`. A revert puts back the exact setup before. On Meta Ads, `list_conversion_actions` lists the account's pixels (datasets); each ad set chooses a pixel and an event, so Meta campaigns have no goals to change here.

## Checking the tracking

`problems` also names what Roasby's fixed checks find: a Microsoft Ads UET tag that receives data while none of its goals records or that no goal uses (`tag_active_no_recording_goal`, `tag_active_without_goals`; Microsoft's API lists no events a tag receives, so tell the user to look at the tag's events, custom events or auto goals in Microsoft Ads, and offer to change or add a goal), primaries that are mostly page views or engagement (`primaries_mostly_engagement`), an account with more conversions than clicks over the 7 settled days (`conversions_above_clicks`), and a Meta pixel event no ad set or custom conversion uses (`pixel_event_unused`). Microsoft Ads accounts list their `tags` with status. ChatGPT Ads events have their 30-day attributed count in `recent_conversions` and are recording when they had one in the last 7 days.

Then judge what fixed rules cannot, from the list itself, and tell the user before proposing a fix: a **category that does not fit** the action's name (for example `exam_finished` under Purchases, `start_trial` under Engagement), and **primary actions that likely count the same person twice** (sign_up and start_trial, purchase and subscription_started, the same event from a tag and from a Google Analytics 4 import). Propose the fix as one batch (`preview_update_conversion_actions`: make the duplicates or engagement secondary, refile categories) and show the preview's campaigns.


A Google Ads conversion action or Microsoft Ads conversion goal can change through `preview_update_conversion_action` and then `update_conversion_action` with the same arguments and the token: `primary` (true: bidding counts it; false: only reported), `counting` (`one` per click for leads and sign-ups, `every` for purchases), `default_value_micros` (the value each conversion gets by default, in micros of the action's `value_currency`: 500 units is 500000000), `always_use_default_value` (true: every conversion gets that value even when the tag sends one), `name`, `category` (on Google Ads also its goal, so it moves to the goal of the new category), `status` (Microsoft Ads: `paused` stops a goal recording but keeps it and its history; Google's API takes no pause, so make a Google Ads action secondary instead; `list_conversion_actions` with `status: hidden` lists the actions Google Ads hides), `click_window_days` (1–90), `view_window_days` (1–30) and `attribution` (`data_driven` or `last_click`). A Google Analytics 4 import takes no attribution (`setting_not_on_conversion_type`), and Google refuses a category change on a GA4 purchase import. On Meta Ads, a custom conversion (`source` `custom_conversion`) takes a new `name` and `default_value_micros`; a pixel takes nothing. Pass the action's `id` (Roasby's) or `platform_id` (the ad platform's) from `list_conversion_actions` as `conversion_action_id`, and only the settings that change. To change many actions of one ad account at once (for example, make 40 secondary and 2 primary), use `preview_update_conversion_actions` with `conversion_actions` (up to 100, each with its `conversion_action_id` and the settings that change) and then `update_conversion_actions` with the same arguments and the token: one confirmation for all, each logged, and `revert_ad_change_batch` undoes them together. `list_conversion_actions` shows the current `default_value_micros`, `value_currency` and `always_use_default_value`.

Before you confirm, read the preview's `details`: it names the campaigns whose bidding counts the action now or after the change (other products' campaigns in the same account too), and on Microsoft Ads that Microsoft turns on auto-tagging of clicks. Tell the user plainly that the change affects **every campaign that bids on this action** (value-based bidding and target ROAS read these values), and that a value change applies to new conversions only. Refusals: `conversion_action_not_synced` (sync first), `conversion_action_shared` (managed in a manager account: change it there), `conversion_action_removed`, `conversion_value_required` (always using the default value needs one: give `default_value_micros` too), `no_change`, `setting_not_on_conversion_type` (a setting the action does not take, a category the platform has not, a Meta pixel), and `kind_not_supported` on ChatGPT Ads. On Microsoft Ads, making a goal secondary needs a feature Microsoft enables only for some accounts: when Microsoft refuses it, say so. A revert puts the settings back as they were.

## Creating a conversion action

`preview_create_conversion_action` and then `create_conversion_action` (same arguments and the token) create one: give `ad_account_id`, `name` and `category`, and what the platform counts. Google Ads makes a webpage action and Roasby makes it secondary at once (the user makes it primary once its tag fires; tell them to add its tag from Google Ads → Goals). Google's API can neither pause nor remove it, so its revert only makes it secondary again. Microsoft Ads makes an event goal on a UET tag (`tag_id` from the account's `tags`, `event_action` as the site sends it, for example the custom event a busy tag already gets), created paused: enable it with `update_conversion_action` (`status: enabled`) once the user confirms. Meta Ads makes a custom conversion on a pixel (`pixel_id`, and `meta_event` and/or `url_contains`); ChatGPT Ads an event on a pixel (`pixel_id` from ChatGPT Ads Manager; the category picks OpenAI's event type). Optional: `counting`, `default_value_micros`, `click_window_days`. Tell the user before confirming that a Meta Ads custom conversion or ChatGPT Ads event **cannot be reverted** (neither platform can pause one; they delete it in the platform if they want it gone), while a Microsoft Ads goal is reverted by pausing it and a Google Ads action by making it secondary (remove it in Google Ads if unwanted). Refusals: `conversion_setup_incomplete`, `uet_tag_not_available` (sync first), `pixel_not_available`, `setting_not_on_conversion_type` (a category the platform has not).
