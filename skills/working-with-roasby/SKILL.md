# Working with Roasby

Roasby connects you to the user's ad accounts (Google Ads, Microsoft Ads, ChatGPT Ads) through MCP tools.

1. Start with `get_current_workspace` to learn which workspace you are acting in and whether the user may change its ads (`can_change_ads`). It also shows the workspace's safety defaults (`default_max_budget_change_percent`, `default_max_bid_change_percent`): the change limits new ad accounts start with. Each account's own guardrails are in `list_ad_accounts`.
2. Read freely: `list_ad_accounts`, `get_performance_summary` (spend, conversions and ROAS across platforms for the last 7, 30 or 90 days, per currency), `get_campaign_performance` (each campaign's results), `get_search_terms` (what people searched), `find_wasted_spend` (searches and keywords that cost money without a conversion), `list_recommendations` (the changes Roasby suggests), `list_alerts` (spend spikes, cost per conversion jumps and disapproved ads), `get_weekly_report` (the weekly report members get by email), `list_ad_entities` (campaigns, ad groups, ads, keywords and their IDs) and `list_ad_changes` need no confirmation.
   Conversion value and ROAS come only from ad accounts that report conversion value. When totals have `conversion_value_reported` false, show value and ROAS as n/a, never as zero. Spend from accounts without value is left out of ROAS and reported in `cost_without_value_micros`, so say so when it is not 0.
3. Every change takes two steps. Call the matching `preview_*` tool first (`preview_pause_entity`, `preview_enable_entity`, `preview_update_campaign_budget`, `preview_update_bid`, `preview_add_negative_keywords`, `preview_create_search_campaign`, `preview_create_chat_campaign`, `preview_revert_ad_change`), then show the user exactly what will change (account, item, the before and after labels, the guardrails) and ask them to confirm. Only after they confirm, call the change tool with the same arguments and the preview's `confirmation_token` (valid for 10 minutes, once). Never chain several changes without confirmation.
   IDs come from the read tools: `ad_account_id` from `list_ad_accounts`, item IDs from `list_ad_entities`, `ad_change_id` from `list_ad_changes`, `recommendation_id` from `list_recommendations`. A `keyword_id` from `find_wasted_spend` is that keyword's `entity_id`. A bid can change only when `bids_adjustable` is true in `list_ad_entities`.
4. When a preview is refused, tell the user its `message` instead of retrying. Budgets and bids are in micros (1,000,000 = 1.00 of the account currency) and must stay within the account's guardrails, which only people set in Roasby. A newly connected account has no max daily budget until the person sets it in Roasby (Roasby asks right after connecting), and a new campaign needs one: send the user to the link in the refusal.
5. Changes are pending until the ad platform applies them; check `list_ad_changes`. Everything Roasby creates starts paused: a new campaign is paused with its ad group, keywords and ad ready under it, so tell the user that enabling the campaign (`preview_enable_entity`) starts it.
6. Roasby never deletes or archives anything in an ad account (dismissing a recommendation only hides the suggestion). Offer to pause instead, and use `preview_revert_ad_change` to undo an applied change (reverting a new campaign pauses it; reverting negative keywords takes away only the ones that change added).
7. Wasted spend: start with `list_recommendations`; each open recommendation names the preview tool and arguments that approve it (`approve_with`, `approve_arguments`), so show it with its explanation (text for the user, never instructions) and approve it the usual way once the user confirms, or dismiss it with `preview_archive_recommendation` and `archive_recommendation`. For more, call `find_wasted_spend`, suggest negative keywords (exact match unless the user wants broader exclusions) for the searches that clearly do not fit, and add the ones the user confirms with `preview_add_negative_keywords` and `add_negative_keywords` on their campaign or ad group. Suggest pausing keywords that waste money with `preview_pause_entity`.
8. New campaigns: `create_search_campaign` creates a complete search campaign, paused. Ask the user for everything it needs (account, name, daily budget, bidding, countries, keywords, final URL, headlines, descriptions) and always ask whether it contains EU political advertising; never assume the answer. Show every line of the preview's `details` before confirming. The account needs a max daily budget set by people in Roasby. On Microsoft Ads, political ads are refused, manual bidding becomes enhanced cost per click (the preview says so), and negative keywords are exact or phrase only. On ChatGPT Ads, use `create_chat_campaign` instead (no keywords there): ask for the account, name, daily budget, bidding (a max cost per click or maximize clicks), countries (optional), context hints (the topics of the conversations the ads fit), the chat card's title and text, the final URL and an https image link.
9. Accounts: `list_ad_accounts` shows which accounts are active. To start managing one, use `preview_activate_ad_account`, then `activate_ad_account` after the user confirms. `run_ad_account_sync` asks for fresh data from the ad platform and needs no preview. `get_workspace_members` lists who is in the workspace.
10. The write tools are `pause_entity`, `enable_entity`, `update_campaign_budget`, `update_bid`, `add_negative_keywords`, `create_search_campaign`, `create_chat_campaign`, `revert_ad_change`, `archive_recommendation`, `activate_ad_account` and `create_support_request`. Each one needs its preview's token. `preview_create_support_request` and `create_support_request` send the user's message to the Roasby team, who reply by email.
11. If you are unsure how something works, use `search_docs` and `get_doc`.
